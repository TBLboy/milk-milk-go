# TASK-104 APP 类型确认改为实时自动扫码抓拍

## 1. 目标

将平板类型确认从“手工拍照后再解析”改为实时摄像扫码：用户点击“打开拍照扫码”后，应用持续识别取景框中的二维码；识别到本系统有效二维码时自动抓拍当前画面、添加现场水印并提交类型确认，无需用户再次点击拍照。

## 2. 业务规则

- 进入扫码界面后由 CameraX 使用后置摄像头提供实时预览；
- 只有解析出 `labelId` 和 `materialId` 的本系统二维码才触发自动抓拍；
- 抓拍照片与识别结果来自同一次现场操作，照片必须添加操作员、时间、工单和步骤水印；
- 识别结果正确时自动调用现有类型确认接口并进入称重步骤；
- 识别结果对应的辅料与当前步骤不一致时，由后端拒绝，界面保持扫码状态并提示错误；
- 连续 5 秒未识别到二维码时，显示无码入口；
- 无码时固定针对当前步骤辅料，现场拍摄包装照片并填写原因后提交后台审批；
- 无码审批通过前不能进入重量确认。

## 3. 范围

- 修改 Android `MainActivity.kt` 的类型确认与扫码界面；
- 引入 CameraX 与 ML Kit 条码识别依赖；
- 复用现有 `confirmStepQr`、`requestStepPhotoApproval`、图片上传、水印和审批接口；
- 不修改后端接口和数据库结构。

## 4. 完成条件

- 扫码界面可打开实时后置摄像头预览；
- 有效自制二维码可自动识别并触发一次抓拍和确认请求；
- 无效码、供应商码和预览二维码不会触发自动确认；
- 错误辅料被后端拒绝后仍可继续扫码；
- 5 秒后可见“没有二维码？拍照申请放行”入口；
- 无码照片必须现场拍摄、填写原因并提交审批；
- Android Debug 构建和 Lint 通过；
- 签名测试 APK 可安装。

## 5. 验证边界

当前本地验证覆盖 Gradle 编译、Lint、APK 构建和模拟器安装启动检查。真实平板的摄像头兼容性、二维码识别距离、抓拍清晰度、自动确认和无码审批联动需要用户安装后现场验收。
