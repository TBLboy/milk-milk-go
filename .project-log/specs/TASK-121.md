# TASK-121 建立响应式布局基线并适配登录页与主框架

## 1. 任务目标与非目标

建立 Android APP 的手机横屏/平板横屏布局判定，并完成登录页、主框架、顶部栏和导航的响应式适配。手机与平板保持完全相同的业务功能、角色权限和导航项。

本任务不修改工作台、工单列表、工单详情、扫码、称重及管理员主数据页面的内部布局；这些由 TASK-122 至 TASK-124 处理。

## 2. 业务原子与验收

- `BL-DEVICE-003`：APP 固定横屏，手机端和平板端功能完全一致，按可用宽高自适应布局。
- `AC-DEVICE-003`：手机横屏所有页面、菜单、按钮和弹窗可到达且无不可恢复的遮挡。
- `AC-DEVICE-004`：同一账号在手机和平板上功能、权限和业务结果一致。
- `DEC-045`：单一横屏 APP，不提供手机精简版或平板独占功能。

## 3. 现有行为

- `AndroidManifest.xml` 已固定 `screenOrientation="landscape"`。
- 登录页使用固定 `420dp` 卡片、`48dp` 外边距和左右并排结构。
- `MainShell` 默认展开固定 `230dp` 侧边栏，手机上会压缩主内容区域。
- 当前只有 `Medium_Tablet` 和 `Pixel_10` 两个 AVD，手机模拟器可用于验证。

## 4. 目标行为

- 定义 `COMPACT` 和 `EXPANDED` 两种横屏布局模式。
- 当可用高度不大于约 `480dp` 或宽度小于约 `600dp` 时使用 `COMPACT` 模式；典型手机横屏进入该模式，典型平板保持 `EXPANDED` 模式。
- 登录页在 `COMPACT` 模式下减小外边距、标题字号和卡片内边距，保留完整登录/注册字段并支持滚动和键盘避让。
- 主框架在 `COMPACT` 模式下默认收起侧边栏，使用较窄导航宽度；用户仍可切换展开。
- 平板保留现有宽屏侧边栏和登录页结构。
- 导航项和业务入口不因设备尺寸减少。

## 6. 接口与数据变化

无外部接口或数据库变化。新增代码只提供 Compose 内部的布局配置数据类和尺寸判定函数。

## 7. 状态与生命周期

- 横屏尺寸变化时重新计算布局模式。
- 手机模式首次进入时收起侧边栏；用户主动展开的状态保留在当前会话。
- 旋转仍受 Manifest 横屏限制，不新增竖屏状态。

## 8. 验证与失败处理

- 手机模拟器验证登录、注册、服务器设置弹窗和主框架导航。
- 平板模拟器验证原有宽屏布局没有明显回归。
- Android 编译和 Lint 必须通过。
- 小屏空间不足时通过滚动、压缩间距和窄侧边栏处理，不隐藏业务功能。

## 9. 安全、隐私与日志

无新增权限、敏感字段、日志或网络请求。登录凭据、服务器地址和后端权限逻辑保持不变。

## 10. 兼容、发布与回滚

- 不新增依赖，不改变 `minSdk`、`targetSdk` 或版本号。
- 若手机布局出现严重回归，可回滚本任务的 UI 修改；业务逻辑无需迁移。
