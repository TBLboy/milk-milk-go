# TASK-115 超差重量不上传证据并禁止提交

## 1. 背景

APP 重量确认当前调用 `submitStepWeight()` 后先上传电子秤读数照片，再请求后端判断重量是否在允许误差内。即使重量超差，照片也已上传并创建 `WeighingAttempt`，与“只有确认成功才能上传信息”的业务要求不一致。

## 2. 业务规则

- 重量确认提交前先进行无照片的允差预校验。
- 预校验检查当前用户权限、步骤状态、重量合法性和目标重量加减允差。
- 重量超差或步骤状态不允许时：
  - 不上传电子秤读数照片；
  - 不创建 `EvidenceFile`；
  - 不创建 `WeighingAttempt`；
  - 不推进步骤状态；
  - APP 显示实际原因并允许重新称重。
- 重量预校验通过后，才允许上传照片并提交正式称重结果。
- 正式提交接口再次校验重量，防止客户端绕过或预校验后配置变化。
- 正式提交接口只保存通过允差校验的称重记录和照片。

## 3. 实施范围

- 后端新增不接收照片的重量预校验接口。
- 提取重量允差校验逻辑，供预校验和正式提交复用。
- APP Repository 在 `uploadImage()` 前调用重量预校验。
- 调整后端正式提交逻辑，使超差请求不创建称重尝试。
- 更新业务原子、需求基线和架构描述。
- 增加正确重量、超差重量和无证据文件回归测试。

## 4. 验收条件

- 正确重量预校验返回成功且不创建证据文件。
- 超差重量预校验返回 `422 WEIGHT_OUT_OF_TOLERANCE`，不创建证据文件或 `WeighingAttempt`。
- APP 源码中重量预校验位于照片上传之前。
- 正式提交接口在缺少照片时仍拒绝成功重量。
- 正式提交接口在重量超差时不创建 `WeighingAttempt`。
- 后端专项与完整回归、Android Kotlin 编译和 Lint、差异检查通过。
- Android `1.0.12` APK 构建、v2/v3 签名和 SHA-256 校验通过。
