# TASK-099 修复 PC 标签预览使用 PREVIEW 导致扫码标签不存在

## 1. 问题

PC 标签生成页在正式生成前使用硬编码的 `labelId = PREVIEW` 构建二维码。
该二维码可被平板扫描，但后台不存在对应的 `labels` 记录，因此类型确认返回
`LABEL_NOT_FOUND`。

## 2. 目标

- 已完成生成的标签预览二维码必须使用后台真实、唯一的 `LBL-*` 标签编号。
- 生成前不得展示可扫描的伪正式二维码。
- 保留现有 `labels` 字符串数组响应，新增 `label_payloads` 供前端生成二维码。
- 标签生成接口必须返回与数据库记录一致的二维码 payload。

## 3. 范围

- `POST /labels/print-batches` 返回 `label_payloads`。
- PC 标签页等待生成成功后再构建预览二维码。
- 生成前显示不可扫描占位提示，放大预览按钮在无标签时禁用。
- 增加后端专项测试。
- PC/后端版本提升到 `1.0.3` 并重新构建 Windows EXE。

## 4. 完成条件

- `label_payloads[].labelId` 与 `labels[]` 和数据库记录一一对应。
- 返回 payload 中不存在 `PREVIEW`。
- 前端不再从辅料信息生成正式二维码。
- 标签专项测试、完整后端回归和 PC 生产构建通过。
- Windows `1.0.3` EXE 生成并通过 SHA-256 校验。

## 5. 验证边界

- 本轮验证 API、数据库、前端构建和安装包构建。
- Windows 11 新装/覆盖安装以及平板实际扫码仍由现场安装验收继续覆盖。

权限级别：B。该修复恢复既有标签身份语义，不改变接口路径或扫码匹配规则。
