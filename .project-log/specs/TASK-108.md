# TASK-108 增强同名辅料扫码不一致诊断

## 1. 背景

用户扫描电脑端新生成的“精制白砂糖”正式标签后，App 返回“扫描到的辅料与当前步骤要求不一致”。排查发现系统中可能存在中文名称相同、但 `materialId` 不同的新旧演示辅料：

- 当前主数据：`MAT-00001 / SWEET-01 / 精制白砂糖`
- 旧演示工单快照：`MAT-00023 / A1 / 精制白砂糖`

扫码校验必须继续以不可变 `materialId` 为准，不能仅因中文名称相同就放行。

## 2. 实施范围

- 后端 `MATERIAL_MISMATCH` 与 `LABEL_MATERIAL_MISMATCH` 返回可读的双方身份信息。
- App 类型确认界面显示当前步骤的 `materialId`。
- PC 工单详情步骤显示 `materialId`。
- 增加同名不同 `materialId` 的回归测试。

## 3. 验收条件

- 不一致响应同时包含当前步骤和扫描标签的辅料名称、内部代号和 `materialId`。
- 同名不同身份不会被错误放行。
- 后端完整测试、PC 生产构建和 Android Kotlin 编译通过。

## 4. 限制

- 本次不改变扫码匹配规则。
- 现有已安装 APK/EXE 尚未重建，真机需要安装后续打包版本才能看到完整诊断文案。
- 旧演示工单与新 Demo 主数据之间的历史身份差异需要按数据迁移或新工单处理，不能通过放宽匹配规则掩盖。
