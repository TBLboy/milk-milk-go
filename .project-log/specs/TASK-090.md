# TASK-090 Windows 覆盖升级配置保留修复

## 1. 背景

Windows 安装器在每次安装时都会把构建包内的 `%ProgramData%\MilkWeigh\config\.env` 复制到客户机配置目录。当前实现没有关闭覆盖写入，因此执行覆盖升级时可能用安装包内置配置覆盖客户机已有的 SMTP、收件邮箱和管理员恢复密钥配置。

这与已确认的部署规则冲突：

- 升级安装必须保留客户机已有数据库和配置；
- 安装包内置配置只负责首次部署零输入初始化；
- 配置轮换必须通过明确的新配置操作完成，不能因普通升级被静默回退。

## 2. 范围

- 修改 `pc/packaging/windows/installer.nsi` 的配置复制逻辑。
- 增加安装器静态回归测试，防止后续重新引入无条件覆盖。
- 不修改数据库、业务 API、前端或 Android App。
- 不重新生成正式发布安装包；仅允许编译临时验证产物。

## 3. 行为要求

### 3.1 全新安装

- 如果客户机配置目录不存在或配置文件缺失，安装器必须写入安装包内置配置。
- `%ProgramData%\MilkWeigh\data` 和 `%ProgramData%\MilkWeigh\logs` 仍按现有逻辑创建。

### 3.2 覆盖升级

- 已存在的 `config\.env` 必须保持原内容不变。
- 已存在的其他配置文件也必须保持原内容不变。
- 新增或缺失的配置文件可以继续从安装包补齐。
- 数据目录和日志目录不得被安装器删除。

### 3.3 权限与安全

- 配置目录继续只授予 `SYSTEM` 和 `Administrators` 完全控制权限。
- 不新增明文配置输出、日志输出或前端可见配置。

## 4. 实现约束

- 采用 NSIS 的 `SetOverwrite off` 包裹配置复制，复制完成后立即恢复 `SetOverwrite on`。
- 保持首次安装与升级使用同一安装器。
- 不引入额外运行依赖或新的配置文件格式。

## 5. 验证

1. 静态回归测试确认配置复制区域同时包含关闭覆盖、配置文件复制、恢复覆盖三个阶段。
2. 使用 NSIS 编译器把修改后的脚本编译到 `.build` 临时目录，确认语法和打包资源有效。
3. 运行后端相关测试、`git diff --check`、Project Log 校验。

真实 Windows 覆盖升级后的配置文件哈希保持不变，仍由 `TASK-083` 在 Windows 11 真机验收。

## 6. 完成边界

本任务只完成安装器修复和可在当前环境执行的静态/编译验证，不把 Windows 真机安装结果伪称为已完成。`TASK-083` 继续负责最终的真实安装、升级、服务、防火墙和数据保留验收。
