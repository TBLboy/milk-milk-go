# TASK-092 BUG 邮件状态、管理员自检与手动重试

## 1. 背景

BUG 反馈会先写入本地数据库，再同步发送邮件。当前邮件发送失败时记录会标记为 `failed`，但管理员无法在电脑端查看失败原因，也无法在 SMTP 恢复后手动重发。

安装期 SMTP 自检只能证明安装当时可用，不能覆盖授权码过期、网络临时中断或邮件服务恢复后的运营场景。

## 2. 范围

- 管理员可查看最近的 BUG 反馈发送状态和脱敏失败原因。
- 管理员可使用当前配置发送一封测试邮件。
- 管理员可对 `failed` 或 `pending` 反馈执行手动重试。
- 重试成功后更新发送状态和时间，并写入审计日志。
- 重试失败保留失败状态和脱敏原因，不影响原反馈内容。
- PC 系统设置页提供对应操作入口。
- 不实现后台自动重试、在线替换 SMTP 凭据或删除 BUG 反馈。

## 3. 接口要求

### 3.1 查看列表

`GET /api/v1/bug-reports`

- 仅管理员可访问。
- 返回最近 100 条，按创建时间倒序。
- 字段包含编号、来源、提交账号、提交人、描述、图片数量、状态、脱敏错误、创建时间和发送时间。

### 3.2 发送测试邮件

`POST /api/v1/bug-reports/smtp-test`

- 仅管理员可访问。
- 使用当前后端 SMTP 配置向固定收件邮箱发送自检邮件。
- SMTP 未配置返回 `503`；发送失败返回 `502`。
- 写入审计日志，不返回或记录授权码。

### 3.3 手动重试

`POST /api/v1/bug-reports/{report_id}/retry`

- 仅管理员可访问。
- 仅允许重试 `failed` 或 `pending` 状态。
- 重新读取原提交人和原图片文件；缺失图片时重试失败并保留明确原因。
- 成功时状态改为 `sent` 并更新 `sent_at`。
- 已发送记录再次请求时返回当前状态，不重复发送。
- 失败时保留 `failed`，更新脱敏错误并返回 `502`。

## 4. 安全与审计

- 列表接口不返回图片文件路径、SMTP 账号、授权码或内部配置。
- 错误摘要最多 1000 字符，不包含 SMTP 授权码。
- 管理员发送测试邮件和重试均记录操作者、记录编号、结果和时间。
- 普通操作员不能访问列表、自检或重试接口。

## 5. 前端要求

- 系统设置页增加“BUG 反馈邮件”面板。
- 显示最近反馈的状态、来源、提交人、时间、图片数量和失败原因。
- 提供“发送测试邮件”按钮，并显示成功或失败反馈。
- 失败记录提供“重试发送”按钮；发送中禁用重复点击。
- 页面继续使用现有自动刷新机制更新状态。

## 6. 验证

1. 后端测试覆盖管理员权限、列表、测试邮件、成功重试、失败重试和已发送幂等。
2. 测试邮件和重试复用现有 SMTP 行为并校验固定收件人。
3. PC TypeScript 生产构建通过。
4. 浏览器验证设置页面板、测试按钮和重试按钮交互。
5. 后端完整回归、`git diff --check`、Project Log 和 Loop 校验通过。

## 7. 完成边界

本任务解决管理员手动恢复能力，不把“SMTP 已提交”表述为收件人一定已读，也不替代 `TASK-083` 的真实 Windows 客户网络验收。
