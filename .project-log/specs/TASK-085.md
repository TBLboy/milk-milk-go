# TASK-085 工程说明：证据完整性检查管理界面

## 1. 目标与非目标

目标：

- 管理员在 PC 系统设置页发起证据文件完整性检查。
- 展示检查时间、总文件数、正常数量、问题数量和异常明细。
- 明确区分 `missing`、`size_mismatch`、`hash_mismatch`、`unhashed`。
- 支持把当前检查发现的异常导出为 CSV。

非目标：

- 不修改证据文件内容、路径或哈希。
- 不自动修复异常文件。
- 不提供普通操作员入口。
- 不改变工单读取、备份或恢复流程。

## 2. 业务与验收关联

- `BL-EVID-001`：生产证据必须可追溯并具备完整性保护。
- `BL-DATA-001`：管理员操作应可审计，异常状态不得伪装成功。
- `AC-WEIGH-001`：称重证据必须可保存、读取和核验。

## 3. 现有行为

- `GET /api/v1/evidence/files/integrity-check` 已存在，仅管理员可调用。
- 后端会逐文件比较磁盘路径、文件大小和 SHA-256。
- 返回 `checked_at`、`total`、`ok`、`issue_count`、`issues` 和 `items`。
- PC API adapter 当前没有该接口方法。
- 系统设置页当前展示称重参数、网络检测、备份操作和历史。

## 4. 目标行为

1. 系统设置页新增“证据完整性检查”面板。
2. 管理员点击“开始检查”后调用现有接口。
3. 检查期间按钮禁用并显示进行中状态。
4. 成功后展示汇总卡片和异常表格。
5. 没有异常时显示明确的正常状态。
6. 有异常时允许导出 CSV，内容来自本次响应，不额外发起请求。
7. 接口失败时显示可见错误，不展示旧结果冒充本次成功。

## 5. 影响模块

- `pc/src/services/api.ts`
- `pc/src/pages/ManagementPages.tsx`
- `pc/src/styles/app.css`

后端接口与数据库结构不变。

## 6. 接口契约

PC adapter 新增：

```ts
checkEvidenceIntegrity(): Promise<EvidenceIntegrityResult>
```

对应接口：

```text
GET /api/v1/evidence/files/integrity-check
```

响应中的异常项至少包含：

```json
{
  "file_id": "FILE-...",
  "status": "missing",
  "expected_sha256": "...",
  "actual_sha256": null,
  "expected_size_bytes": 123,
  "actual_size_bytes": null
}
```

## 7. 状态与错误处理

- 初始状态：尚未检查。
- 加载状态：禁用重复提交，显示“正在检查...”。
- 成功状态：替换当前结果并显示检查时间。
- 失败状态：保留错误提示；结果区域明确不可用。
- 空数据：`total=0` 视为成功，显示暂无可检查证据。
- CSV：只有当本次 `issue_count > 0` 时启用。

## 8. 安全与隐私

- 页面仅存在于管理员设置页。
- 后端 `require_admin` 是权限的权威边界，前端隐藏不作为安全措施。
- 导出内容只包含证据文件 ID、状态、大小和哈希，不包含图片内容。
- 页面不展示本地绝对路径。

## 9. 兼容与回滚

- 无数据库迁移。
- 无新增持久化设置。
- 回滚只需移除页面入口、adapter 方法和样式，不影响后端数据。

  - 点击检查后显示汇总。

  - 模拟异常响应时异常表格与 CSV 导出可用。
