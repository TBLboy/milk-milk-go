# TASK-105 修复 APP 实时二维码识别率低

## 1. 问题

PC 标签页生成的二维码可被浏览器扫码识别，但 Android APP 长时间无法识别。初步代码核查确认类型确认扫码使用 CameraX 默认 `ImageAnalysis` 分辨率，且没有针对小尺寸二维码启用自动缩放；标签预览中的二维码在普通预览状态下可能只有约 76-104 CSS 像素，容易低于 ML Kit 当前分析流中的可识别像素量。

## 2. 修复目标

- 提高 CameraX 分析流分辨率，保留较低的帧率压力；
- 将 ML Kit 限制为二维码格式，减少无关条码检测开销；
- 启用 ML Kit 自动缩放建议，由 CameraX 在二维码过小时自动拉近；
- 增加识别状态提示，区分“未识别”“已检测但未解析”“非本系统二维码”；
- 保持现有自动抓拍、水印、类型确认和无码审批逻辑不变。

## 3. 业务规则

- 只有能解析出 `labelId` 和 `materialId` 的本系统二维码可以自动确认；
- 非本系统二维码不得自动确认，并显示明确提示；
- 自动缩放只影响识别过程，不改变最终抓拍和证据照片；
- 无码入口和 5 秒等待规则保持不变。

## 4. 验证边界

本地执行 Android Debug 构建、Lint、签名 APK 构建、SHA-256 和模拟器安装启动检查。真实平板的识别距离、屏幕二维码大小、瓶身弧度、自动缩放效果和扫描成功率需要用户安装 `1.0.5` 后现场验收。
