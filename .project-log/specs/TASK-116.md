# TASK-116 重量读数变化或提交失败后作废旧照片

## 1. 背景

重量确认失败后，APP 仍保留上一次拍摄的电子秤读数照片。操作员修改重量后可以直接复用旧照片提交，导致系统记录的新数字重量与照片中的旧读数不一致。

## 2. 业务规则

- 电子秤读数照片必须对应当前输入的数字重量。
- 操作员修改重量读数后，上一张照片立即失效并从界面清除。
- 重量提交校验失败后，上一张照片立即失效并从界面清除。
- 照片失效后，提交按钮必须重新禁用，操作员必须重新拍摄当前电子秤读数。
- 本地缓存中的待提交照片应尽力删除，避免下一次误用。
- 重新拍照成功后，才恢复提交能力。

## 3. 实施范围

- `ProcessedEvidence` 保留处理后照片文件引用。
- `WeightDialog` 统一清理照片 URI、文件名和本地缓存文件。
- 重量输入发生变化时清理旧照片。
- 重量提交失败时清理旧照片。
- 相机取消、照片处理失败或关闭弹窗时清理未提交文件。

## 4. 验收条件

- 输入读数并拍照后，修改读数会清除照片并禁用提交。
- 超差提交失败后，照片状态被清除并禁用提交。
- 操作员重新填写新读数后，必须重新拍照才能提交。
- 重新拍照成功后可以再次提交。
- Android 编译、Lint、静态检查、签名 APK 构建和差异检查通过。

## 5. 验证结果

- Android `:app:compileDebugKotlin` 与 `:app:lintDebug` 通过。
- 静态检查确认：重量输入变化、提交结果处理和提交异常分支都会调用 `clearPhotoEvidence()`。
- `ProcessedEvidence` 已保留处理后照片文件引用，统一清理逻辑会删除待提交缓存。
- Android `1.0.13`（`versionCode=14`）APK 已构建，v2/v3 签名通过。
- APK SHA-256：`3a850fc209afef8e3da06ddaa965cb99a6316bdd586e46f323fcc663c6afdee4`。
- 证据：`EV-TASK-116-ANDROID-BUILD-LINT`、`EV-TASK-116-STALE-PHOTO`、`EV-TASK-116-APK`、`EV-TASK-116-DIFF`。

## 6. 限制

- 真实 Android 平板需人工回归“旧照片失效”和“必须重新拍照”交互。
- Android 系统缓存目录可能延迟回收已删除文件，但 APP 不会再引用该文件并可正常重新拍摄。
