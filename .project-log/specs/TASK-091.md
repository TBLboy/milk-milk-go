# TASK-091 Windows 安装后 SMTP 非阻塞自检

## 1. 背景

Windows 安装包已经实现构建时注入 SMTP 配置、首次安装写入配置并由后台服务读取。但安装完成后不会主动验证 SMTP 配置是否可用。

如果授权码失效、客户网络无法访问 `smtp.qq.com` 或出站 `465` 端口被拦截，问题只会在用户第一次提交 BUG 反馈时暴露。该步骤需要补齐安装时自检和失败提示。

## 2. 范围

- 增加安装期 SMTP 自检脚本。
- 安装器启动后台服务后调用自检脚本，并设置有限超时。
- 自检成功或失败都写入脱敏日志。
- 自检失败只显示警告，不撤销安装、不阻断后台服务。
- 增加静态和脚本级回归测试。
- 不实现在线替换 SMTP 凭据、邮件重试队列或真实 Windows 邮件投递验收。

## 3. 行为要求

### 3.1 自检成功

- 使用 `%ProgramData%\MilkWeigh\config\.env` 中的现有配置。
- 连接配置的 SMTP 主机和端口。
- 使用现有发件账号登录，并向固定收件地址提交一封简短测试邮件。
- 在 `%ProgramData%\MilkWeigh\logs\smtp-install-test.log` 写入成功记录。
- 进程退出码为 `0`。

### 3.2 自检失败

- SMTP 未配置、连接失败、认证失败或发送失败时返回非零退出码。
- 日志包含失败类别和经过脱敏的错误摘要。
- 日志和安装器输出不得包含 SMTP 授权码、管理员恢复密钥或完整 `.env` 内容。
- 安装器显示明确警告，提示系统已安装但邮件反馈可能在修复配置前不可用。
- 安装器不得因自检失败调用 `Abort` 或删除已安装文件。

### 3.3 超时

- 安装器对自检设置明确的超时上限，避免网络不可达时长时间卡住安装流程。
- 超时按失败处理，并显示与普通失败一致的警告。

## 4. 实现约束

- 自检脚本使用 Python 标准库和项目现有 `Settings`，不新增运行依赖。
- 自检脚本必须使用客户机 `%ProgramData%` 下的配置，不读取构建机配置。
- 配置文件缺失时仍保持后台服务可启动，由 BUG 反馈接口返回明确的未配置错误。
- 收件地址继续使用系统固定的 `bug_report_recipient`。

## 5. 验证

1. 自检脚本单元测试覆盖配置缺失、成功发送、失败脱敏和日志写入。
2. 静态测试确认构建脚本复制自检脚本、安装器调用脚本且使用有限超时。
3. 修改后的 NSIS 脚本可以编译到 `.build` 临时目录。
4. 后端完整测试、`git diff --check`、Project Log 和 Loop 校验通过。

真实 Windows 11 网络环境中的 SMTP 提交结果仍由 `TASK-083` 验收。

## 6. 完成边界

本任务完成安装期自检代码、告警和本地可验证证据，不宣称真实客户网络已能发送邮件，也不替换现有授权码轮换和后台重试能力。
