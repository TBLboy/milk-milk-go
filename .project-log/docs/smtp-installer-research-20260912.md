# SMTP 授权码有效期与 Windows 安装一键配置调研

- 调研日期：2026-09-12
- 关联功能：TASK-062 BUG 反馈邮件
- 调研范围：QQ 免费邮箱 SMTP 直接发信、Windows 11 客户端安装、首次配置和授权失效兜底
- 约束：不部署中央邮件中转服务，不引入固定月费，收件地址固定为 `1218740205@qq.com`

## 结论摘要

1. SMTP 协议本身不存在“授权码永久有效”这一概念。
2. QQ 免费邮箱的 SMTP 授权码没有找到官方“永久有效”承诺，不能把它当作永久凭据。
3. 授权码更像一个长期使用的可撤销密码。正常状态下通常可以持续使用，但邮箱安全设置、账号状态或腾讯服务规则变化都可能使它失效。
4. 可以通过 Windows 安装向导实现一次录入、自动测试、加密保存的一键配置。但如果没有中央服务，也没有预置密钥，就无法同时做到“用户零输入”和“凭据不落入安装包”。
5. 本项目的推荐方案是：安装向导输入一次发件邮箱和授权码，点击“测试并保存”，后端测试 SMTP 登录和投递，再用 Windows DPAPI 加密保存。客户日常使用不再接触授权码。

## 1. SMTP 授权码是否永久有效

### 1.1 准确结论

不建议使用“永久有效”来描述 QQ 邮箱 SMTP 授权码。

更准确的表述是：

> QQ 邮箱 SMTP 授权码通常可以长期使用，但它是一项可被用户、腾讯或账号安全策略撤销的凭据，不存在已经确认的永久有效保证。

截至本次调研，腾讯 QQ 邮箱公开帮助中心没有给出“SMTP 授权码永久有效”的保证；腾讯企业邮箱帮助中心则明确使用“客户端专用密码”模型，生成后的密码可以持续使用，但每一条可以单独停用，关闭安全登录后全部生成密码立即失效。该规则可作为理解腾讯邮箱凭据生命周期的佐证，但不能直接等同于免费 QQ 邮箱的正式承诺。

### 1.2 可能失效的情况

- 用户重新生成或重置授权码，旧授权码通常失去作用。
- 用户关闭 QQ 邮箱的 POP3/SMTP 服务。
- 开启“邮箱登录保护”。腾讯官方说明，开启后客户端代收方式 `POP3/SMTP/IMAP` 将无法使用。
- QQ 账号被冻结、停用、回收或出现安全限制。
- 腾讯调整客户端服务、安全策略或授权码规则。
- 邮箱发送大量异常邮件后被限制或封禁。

因此系统不能只做“配置一次以后不再检查”。至少需要保存失败状态、自动重试和管理员测试入口。

### 1.3 运营建议

- 使用专门的发件邮箱，不混用个人日常邮箱。
- 在发件邮箱中保持 POP3/SMTP 服务开启。
- 不要开启会禁止 `POP3/SMTP/IMAP` 的邮箱登录保护。
- 在安装时验证一次，部署后提供“发送测试邮件”按钮。
- 授权码失效时允许管理员在后台替换，不需要重新安装系统。

## 2. 安装时一键配置的可行方案

### 2.1 方案 A：安装向导录入并测试保存，推荐

安装流程：

1. 安装人员输入专用发件邮箱和 SMTP 授权码。
2. 点击“测试并保存”。
3. 安装程序调用后端配置工具。
4. 配置工具连接 `smtp.qq.com:465`，执行 TLS 握手、登录并发送测试邮件。
5. 测试成功后，授权码使用 Windows DPAPI 加密。
6. 加密密文保存到 `%ProgramData%\MilkWeigh\config\`。
7. Windows 服务启动时读取配置；安装人员无需手工编辑 `.env`。
8. 升级安装包时不覆盖已有配置。

优点：

- 不把授权码写进安装包。
- 安装时即可发现邮箱未开启、授权码错误、端口被防火墙拦截等问题。
- 每台客户机器可以使用独立凭据，泄露影响范围较小。
- 后续可在后台替换授权码，不需要重新安装。

代价：

- 首次安装仍需安装人员输入一次邮箱和授权码。
- 这里所说的“一键配置”是指点击一次“测试并保存”后自动完成验证和落盘，不是客户完全零输入。

### 2.2 方案 B：受控配置文件导入

为批量部署准备一个配置文件，安装程序读取后自动导入、测试和加密保存。

该方案可以实现安装人员少输入，但配置文件本身仍包含或间接保护授权码，必须满足以下条件：

- 文件必须有访问控制和有效期。
- 文件导入成功后应立即删除。
- 不通过命令行参数传输明文授权码。
- 不把配置文件长期放在安装目录或 Git 仓库。

如果没有安全密钥交付渠道，这个方案只是把手工输入换成了文件复制，并不会消除凭据泄露风险。

### 2.3 方案 C：把授权码内置到安装包

不建议采用。

安装包可以被解压、复制和分析，内置授权码一旦泄露，任何人都可以冒用发件邮箱。即使使用简单的对称加密，只要安装程序能在客户电脑上自动解密，授权码就仍然可以被提取。

### 2.4 方案 D：安装后在后台配置

安装时不配置，由管理员登录后台后填写和测试。

优点是最安全、最简单；缺点是每次部署都需要后续操作，不符合“安装时一键配置”的目标。可以作为方案 A 的降级入口，但不建议作为主流程。

## 3. 推荐的一键配置结构

### 3.1 安装向导

安装向导新增“邮件反馈配置”页，至少包含：

- 发件邮箱
- SMTP 授权码
- “测试并保存”按钮
- 当前状态、错误原因和重试提示
- “稍后配置”入口

收件邮箱 `1218740205@qq.com` 可以固定，不需要客户填写。

### 3.2 配置工具接口

建议新增后端或安装期配置工具，例如：

```text
milk-weigh-config smtp set --username <发件邮箱> --password-file <临时文件> --test
```

约束：

- 授权码不要直接放在命令行参数中。
- 配置工具优先从标准输入或受限临时文件读取授权码。
- 导入成功后立即删除临时明文文件。
- 测试失败时不得覆盖上一份有效配置。

### 3.3 保存位置和加密

推荐的生产结构：

```text
%ProgramData%\MilkWeigh\
  config\
    app.json
    smtp.cred
  data\
  backups\
  logs\
```

其中：

- `app.json` 保存非敏感配置，如 SMTP 主机、端口、发件邮箱和收件邮箱。
- `smtp.cred` 保存经 Windows DPAPI 加密的授权码。
- `%ProgramData%\MilkWeigh` 仅允许管理员、系统服务和后端服务账号访问。
- 开发和测试环境可以继续使用 `.env`，生产安装不应依赖明文 `.env`。

安全边界：

- DPAPI 可以避免授权码以明文文件形式直接泄露。
- 如果使用机器范围的 DPAPI，拥有本机管理员权限的人仍可能解密或从运行中的服务中取得凭据。
- 这适合防止普通用户误读、文件误复制和备份泄露，不应当宣传为能够抵抗本机管理员攻击。
- 如果后续需要更强隔离，应让后端服务使用专用 Windows 服务账号，并使用绑定该账号的用户范围 DPAPI 或 Windows Credential Manager。

### 3.4 测试邮件

安装配置页的“测试”不应只检查端口，应当完成：

1. DNS 解析 `smtp.qq.com`。
2. 建立 `465` 端口 TLS 连接。
3. SMTP 登录。
4. 向固定收件地址发送一封简短测试邮件。
5. 显示 SMTP 服务器是否接受邮件。

SMTP 接受不等于对方邮件系统最终一定投递成功，因此界面文案应写“测试邮件已提交”，不要承诺“已送达”。实际收件需由维护人员确认。

## 4. 授权码失效后的兜底

即使使用专用邮箱，也建议增加以下保护：

- BUG 提交先写入本地数据库，邮件失败不能丢失反馈内容。
- 发送失败保留 `pending` 或 `retry` 状态，并按 1 分钟、5 分钟、30 分钟、6 小时等间隔重试。
- 后台增加“BUG 反馈”列表，显示发送状态、失败时间、错误摘要和重试按钮。
- 后台增加“发送测试邮件”按钮，用于排查授权码和网络问题。
- SMTP 授权失败时在管理端显示明确告警，而不是只在单次提交时提示。
- 允许管理员在线替换发件邮箱和授权码。
- 升级安装包必须保留 `%ProgramData%\MilkWeigh\config\`。

## 5. 网络前提

该方案要求后端电脑能够访问互联网和腾讯 SMTP 服务。客户现场即使局域网可用，也必须确认：

- `smtp.qq.com` 可解析。
- 出站 `TCP 465` 未被防火墙或代理拦截。
- 客户电脑允许后台服务发起外网连接。

如果工厂网络完全隔离，BUG 邮件只能在网络恢复后重试发送；反馈内容仍需先保存在本地数据库。

## 6. 推荐决策

建议第一版采用：

- 专用 QQ 发件邮箱
- 安装向导一次录入
- “测试并保存”一键配置
- Windows DPAPI 加密授权码
- 后台在线替换和发送测试
- 本地保存反馈并失败重试

不建议：

- 把授权码内置到安装包
- 把授权码提交到 Git
- 将“授权码长期可用”误解为“永久有效”
- 在没有本地队列的情况下把 SMTP 成功当作反馈保存成功的唯一条件

## 7. 已确认的零输入安装变体

用户已明确要求安装包采用零输入部署，并接受凭据内嵌风险。

后续 Windows 安装包按以下规则实现：

1. 构建机上的 `pc/server/.env` 是 SMTP 凭据的唯一构建源。
2. 打包脚本读取发件邮箱、授权码和固定收件邮箱，生成临时内置配置资源。
3. 安装程序把配置自动写入客户机配置目录并启动后端服务。
4. 安装过程不显示 SMTP 输入页，不要求安装人员填写任何信息。
5. 安装结束后异步执行 SMTP 测试；失败时显示警告并记录脱敏错误，不阻断核心系统安装。
6. 构建日志、安装日志和应用日志必须过滤授权码。
7. 授权码轮换后必须重新构建并分发安装包，或使用后续定义的受控配置更新包。

该变体的代价是安装包可以被提取并取得 SMTP 凭据。由于用户明确接受该风险，本项目按零输入优先实现。

## 9. 限制和未决项

- QQ 免费邮箱是否会在特定安全事件中使已有授权码失效，官方帮助未给出完整规则。
- 腾讯企业邮箱的“客户端专用密码”规则与免费 QQ 邮箱相似，但不是对免费 QQ 邮箱的正式有效期承诺。
- 当前后端仍是 `.env` 明文配置，尚未实现安装向导、DPAPI 配置工具、后台测试邮件和失败重试。
- 是否需要每个客户使用独立发件邮箱，需要根据部署规模和可接受的凭据维护成本决定。
