## 1. 产品定位

### 1.1 一句话定位

这是一个部署在牛奶生产企业内部局域网中的**辅料称重防错与生产追溯系统**。

系统通过以下方式降低辅料操作错误：

1. 按产品配方和目标生产重量计算每种辅料应称取的重量。
2. 要求操作员按顺序完成每种辅料。
3. 通过公司自制二维码确认辅料类型正确。
4. 通过手动输入重量和现场拍摄电子秤读数照片确认重量证据。
5. 保存二维码、照片、重量、人员、时间、审批和操作日志。
6. 让管理员能够追溯每一个工单和每一份证据。

### 1.2 当前明确不做的事情

第一版不包含：

- 金蝶或其它 ERP 对接；
- 供应商原二维码、条码解析和映射；
- 后端模型自动识别辅料包装图片；
- 电子秤串口或蓝牙实时读数；
- 平板离线队列；
- 库存、采购、财务、生产调度；
- 批次、实际生产日期、有效期和到期日期管理；
- 物理删除生产工单和证据；
- 扫码枪作为第一版主流程；
- 面向公网的多租户 SaaS 服务。

## 2. 系统边界与部署形态

### 2.1 组成

| 部分 | 当前形态 | 主要职责 |
|---|---|---|
| PC 后端 | Windows 11 上的 FastAPI 服务 | 账号、权限、数据库、API、文件证据、审批、标签记录、备份 |
| 数据库 | SQLite | 主数据、工单、步骤、确认、称重、审批、标签、日志和账号 |
| 文件存储 | 后端电脑本地目录 | 包装图片、生产证据照片、头像、Excel、备份文件 |
| PC 管理端 | React + Vite 浏览器页面 | 管理、审批、打印记录、账号、设置和追溯查看 |
| 平板端 | Android 原生 Compose App | 现场创建工单、拍照扫码、称重拍照、申请和查看状态 |
| 网络 | 局域网 WiFi | 平板通过 PC 主机 IP 和端口访问后端 |
| 打印 | Windows 打印能力预留 | 第一版标签打印链路尚未真正完成 |

### 2.2 当前运行参数

- 后端默认监听端口：`8011`
- PC 管理端可由后端同端口提供
- Android App 通过 `http://主机IP:8011/api/v1/` 访问
- 核心生产流程不依赖互联网
- BUG 反馈邮件依赖 SMTP 和外网，但失败不阻塞核心生产流程
- 多台平板可以同时访问同一后端

### 2.3 已确认技术边界

- 电脑端优先 Windows 11。
- 平板端按最新 Android 系统适配。
- PC 使用浏览器管理端，同时准备 Windows 安装包。
- Android 使用 APK 安装包。
- 安装包计划内置数据库自动备份能力。
- 第一版不连接电子秤硬件。

## 3. 用户角色与权限

| 角色 | 所在端 | 已确认权限 |

### 3.1 账号规则

- 平板注册只能创建普通操作员账号。
- 注册申请必须由后台管理员审批，审批通过前不能登录。
- 管理员账号由系统预置或后台管理，不开放公开注册管理员。
- 普通操作员不能登录 PC 管理端。
- 账号资料包含显示名、头像、电话和身份证。
- 普通用户只维护自己的头像、姓名和电话，身份证只读。
- 管理员可以维护普通账号资料。
- 身份证在账号列表和非本人场景中脱敏。
- 管理员不能直接查看用户密码。
- 管理员重置密码时由后端生成一次性随机初始密码。
- 初始密码只展示一次，关闭弹窗后不再可见。
- 用户首次使用重置密码登录后必须修改密码。
- 用户可在个人资料中凭当前密码自助修改密码。
- PC 登录页存在管理员紧急恢复机制，恢复口令只在后端哈希校验，明文不进入前端或 Git。

### 5.6 类型确认

当前实现采用统一的“拍照扫码”：

1. 点击“拍照扫码”打开应用内相机；
2. 拍摄当前辅料包装；
3. 系统从同一张照片尝试解析二维码；
4. 照片添加操作员、时间、工单、步骤或辅料水印；
5. 上传照片作为证据；
6. 二维码包含本系统 `materialId` 时与工单当前步骤比较；
7. 匹配则允许进入称重；
8. 未识别到二维码时填写原因并提交后台拍照审批；
9. 拍照申请未通过前不能称重。

已修复的旧问题：

- 曾经打开类型确认后自动填入正确辅料，无需扫码就已通过；
- 曾存在扫码后界面无反应的问题；
- 曾存在拍照或扫码时 App 闪退的问题。

生产照片规则：

- 类型确认和称重证据只能通过 App 现场相机拍摄；
- 不能从系统相册选择生产证据；
- 生产照片必须添加水印；
- 头像和辅料包装图片不属于生产证据，可选择相册或拍摄。

### 5.7 重量确认

第一版不连接电子秤：

1. 操作员读取电子秤实际读数；
2. 在 App 手动输入重量，单位为 kg；
3. 使用 App 现场拍摄电子秤读数照片；
4. 数字重量和照片必须同时提交；
5. 后端按目标重量和允差判断；
6. 在允差内才允许步骤完成；
7. 超差时保留称重尝试，但不完成步骤，操作员需要调整后重新称量。

## 6. 端到端真实工作流

### 6.1 准备工作

1. 在电脑或平板由管理员创建辅料。
2. 录入辅料内部代号、中文名称、可选英文名称、保质期和包装图片。
3. 创建产品。
4. 从现有辅料库选择配方辅料。
5. 录入每种辅料的每吨用量。
6. 给辅料生成、打印和粘贴公司自制二维码标签。
7. 普通操作员注册账号并等待管理员审批。

### 6.2 创建工单

1. 操作员在平板登录。
2. 选择产品或由管理员在 PC 创建工单并指定操作员。
3. 输入目标生产重量。
4. 系统按配方快照生成辅料步骤和应称重量。
5. 工单进入待审批。
6. 管理员批准后，工单绑定到指定操作员。

### 6.3 执行一个辅料步骤

1. 操作员按顺序打开当前步骤。
2. 拍当前辅料包装并自动尝试扫码。
3. 系统核对 `materialId`。
4. 类型正确后进入称重。
5. 操作员调整重量。
6. 手动输入电子秤读数。
7. 拍摄电子秤读数照片。
8. 系统按允差判断。
9. 重量正确后完成当前步骤。
10. 进入下一种辅料。

### 6.4 完成工单

1. 所有辅料步骤按顺序完成。
2. 每种辅料都有类型确认证据。
3. 每种辅料都有数字重量和电子秤读数照片。
4. 没有未完成的中间步骤。
5. 操作员提交完成。
6. 系统保存完整生产记录。

### 6.5 异常流程

| 异常 | 当前处理 |
|---|---|
| 二维码缺失、污损或无法识别 | 拍照、填写原因、提交后台审批 |
| 扫到错误辅料 | 禁止进入称重 |
| 图片上传失败 | 保留当前步骤，提示重试 |
| 重量超差 | 不完成步骤，要求调整后重新称量 |
| 未拍到电子秤读数 | 禁止提交 |
| 平板断网 | 第一版不做离线队列，恢复网络后继续 |
| 工单被其他设备更新 | 返回冲突，刷新后继续 |
| 接管或撤销 | 提交申请，等待管理员审批 |
| 标签打印失败 | 目标设计为阻止确认并提示检查打印机 |
| 标签打印结果未知 | 目标设计为人工核对，不能无依据重打 |

## 7. 关键数据和业务规则

### 7.1 辅料身份

- `materialId` 是系统内部稳定身份。
- 中文名称可以变化。
- 内部代号是现场业务代号。
- 二维码匹配应以 `materialId` 为核心，不依赖中文名称。
- 第一版不解析供应商原码。

### 7.2 配方

- 配方单位：每吨成品所需辅料重量。
- 目标生产重量用于等比换算。
- 工单保存创建时的配方快照。
- 配方后续修改不影响已有工单。

### 7.3 工单状态

当前代码存在以下状态：

- 待审批；
- 已批准；
- 执行中；
- 已完成；
- 已撤销；
- 历史兼容的已删除。

业务上新的删除申请已取消，仅保留撤销。撤销后仍保留全部历史记录和证据。

### 7.4 步骤状态

- 待处理；
- 类型确认中；
- 待无码审批；
- 待称重；
- 已完成。

后端只允许当前步骤推进，正常流程不能跳步。

### 7.5 称重规则

- 单位：kg 净重。
- 第一版来源：手动输入。
- 必须同时存在电子秤读数照片。
- 默认相对允差：目标重量的 1%。
- 最小绝对允差：5 g。
- 实际允差取两者中的较大值。
- 允差可在设置中调整。
- 超差尝试保留但不完成步骤。

### 7.6 证据和留存

- 类型确认、称重照片、审批、打印和日志长期保存。
- 第一版不设置清除期限。
- 撤销不删除证据。
- 服务器时间作为主要审计时间。
- 生产照片带操作员、时间、工单和步骤或辅料水印。

## 8. 安全和隐私现状

### 8.1 已实现

- 后端重新校验角色，不信任前端隐藏菜单。
- 普通操作员不能进入 PC 管理端。
- 密码保存单向哈希。
- 登录令牌有过期时间。
- 管理员重置密码使用一次性随机密码。
- 重置密码后首次登录强制修改。
- 身份证在非必要场景脱敏。
- 文件读取经过权限控制。
- 文件上传校验类型和大小。
- SQLite、证据目录和配置目录不直接作为静态目录公开。
- 关键操作写审计日志。
- 系统主要在内网使用。

### 8.2 需要重点审查

- 局域网当前使用 HTTP 明文，登录令牌可能被同一网络内攻击者截获。
- SQLite 中敏感个人信息是否需要在应用层增加加密或字段级保护。
- 客户端生成的图片水印不能单独证明照片一定来自真实相机，需要评估防伪强度。
- 当前生产证据依赖人工拍照和人工输入称重，系统不能证明秤面读数与数字输入完全一致。
- 备份文件是否包含未加密证据和个人信息需要明确。
- SMTP 凭据通过安装包携带存在泄露风险，需要评估 DPAPI、一次性配置或替代通知方式。
- 用户协议需要客户法务确认，不能仅凭开发方文本视为完整合规闭环。
