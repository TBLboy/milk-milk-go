# 生命周期与阶段门 v0.2

## 使用原则

阶段是决策和证据边界，不是强制瀑布。小改动可以合并阶段，但不能跳过相应判断。`prototype`、`hotfix` 和 `research` 模式允许简化，但必须记录被延期的风险和后续补偿任务。

## 1. business-intent

**目标：** 明确为什么做、为谁做、希望改变什么，以及本轮范围。

**进入输入：** 用户诉求、现有项目背景。

**退出条件：**

- 目标用户或操作者已知；
- 核心问题和预期业务结果已描述；
- 本轮范围边界初步明确；
- 已建立 active goal。

**默认 Skill：** `a-business-clarify`（意图仍模糊时）。

## 2. business-clarification

**目标：** 在同一生命周期阶段内分别澄清功能业务逻辑、技术业务逻辑，并完成双向对齐。

**退出条件：**

- 主流程和高影响分支已覆盖；
- 关键异常、权限、失败和边界已覆盖；
- 与本次增量相关的当前实现、接口、数据、一致性、并发和兼容事实已调查；
- 功能规则与当前技术事实的匹配、漂移、冲突和未知已登记；
- 高影响未知项已解决或显式挂起；
- 原子规则可单独验收；
- 没有阻塞实现的 C 级问题；
- 未来技术方案问题已转入 solution-research。

**Skill：** `a-business-clarify`。

## 3. requirement-baseline

**目标：** 形成当前增量暂时稳定的业务合同。

**退出条件：**

- 范围内原子为 `active` 或明确 `experimental`；
- 每个原子有验收条件；
- in-scope/out-of-scope、约束、假设和未决问题明确；
- 基线版本和审批证据已记录。

**Skill：** `a-requirement-baseline`。

## 4. solution-research

**目标：** 确认实现约束，比较成熟方案，选择使用/封装/参考/自研/试验。

**退出条件：**

- 问题和约束精确；
- 严肃候选使用统一维度比较；
- 核心结论有一手或官方证据；
- 推荐策略、条件、风险和 fallback 明确；
- 高影响取舍已按权限处理。

**Skill：** `a-solution-research`。

## 5. architecture-decision

**目标：** 固定当前增量需要的职责、接口、数据、状态、故障和运行边界。

**退出条件：**

- 模块责任和接口明确；
- 关键数据流、状态所有权和失败路径明确；
- 安全、可观测、部署和兼容约束已处理；
- 重大决策进入 decision-log；
- 足以进行任务拆解，不需要发明新业务规则。

**Skill：** `a-architecture-decision`。

## 6. task-decomposition

**目标：** 把目标拆为依赖明确、可独立验收的执行图。

**退出条件：**

- 范围内业务原子均有任务覆盖或明确无需改动；
- 依赖、阻塞、输入输出和权限明确；
- 没有无法解释的大任务黑箱；
- 下一 ready task 可机械选择。

**Skill：** `a-task-decompose`。

## 7. engineering-spec

**目标：** 描述任务具体修改边界和验证方法。

**退出条件：**

- 目标/非目标、现状/目标行为明确；
- 模块、接口、数据、错误、并发、可观测和兼容策略明确；
- 测试矩阵和回滚策略明确；
- 实现者无需重新猜测业务意图。

**Skill：** `a-engineering-spec`。

## 8. implementation

**目标：** 按基线、架构和工程说明完成最小一致改动。

**退出条件：**

- 计划内输出已经生成；
- 局部静态检查和测试通过，或失败/限制已记录；
- 未引入未经记录的产品行为；
- 偏离说明和 follow-up 已更新。

**Skill：** `a-engineering-landing`。

## 9. verification

**目标：** 用可追溯证据证明实现满足业务验收条件。

**退出条件：**

- 每个相关验收项都有验证 disposition；
- 关键失败、边界和回归已检查；
- 环境限制被明确标注；
- 未验证项不能伪装成 done。

**Skill：** `a-verification`。

## 10. alignment

**目标：** 检查业务、基线、架构、代码、配置和测试是否一致。

**退出条件：**

- 双向审计完成；
- 所有差异已分类；
- 可安全修复项已修复并验证；
- 冲突项形成用户决策或后续任务；
- 追溯关系已更新。

**Skill：** `a-business-code-align`。

## 11. retrospective

**目标：** 识别有效做法、返工、根因和流程摩擦。

**退出条件：**

- 记录 worked、failed/reworked、root causes；
- 改进项进入任务；
- 知识候选有证据和置信度。

**Skill：** `a-retrospective`。

## 12. distillation

**目标：** 把重复验证的经验晋升为个人规则、Skill、Agent、模板或插件候选。

**退出条件：**

- 适用条件、反例、风险和证据明确；
- 高风险偏好已获用户批准；
- 编码资产具有评估计划；
- 一次性做法未被直接永久化。

**Skill：** `a-operator-distill`。
