# 架构设计前待细化确认点

> 用途：整理第一版进入架构设计前还需要的用户确认输入。
> 当前阶段：solution-research。

## 确认状态

- 用户已同意本文全部建议默认值。
- 平板按最新 Android 系统适配，并支持安装 APK。
- 后端默认按 Windows 11 部署，Windows 支持安装系统软件。
- 安装包内置自动备份数据库。
- 本文后续作为架构设计输入，不再作为待确认问题。

## A. 称重业务口径

1. 重量单位和小数精度
   - 建议：操作员统一输入 kg，保留 2 到 3 位小数；界面可根据现场习惯切换 g/kg。

2. 称重结果是毛重还是净重
   - 建议：第一版记录“材料净重”，操作员称量前先把容器清零或记录皮重后归零。
   - 需要确认：现场是否允许容器先清零，还是必须输入材料+容器重量并单独计算皮重。

3. 电子秤读数照片拍到什么
   - 建议：照片中同时出现辅助材料/容器和电子秤读数，不能只拍屏幕。
   - 需要确认：现场是否能一次把材料和秤面读数放进同一画面。

4. 默认允差
   - 建议：默认取目标重量的 1% 和 5g 中较大值，可在设置界面按辅料或配方调整。
   - 需要确认：客户是否接受这个默认值。

## B. 主数据与工单数据

5. 配方修改后，已创建工单是否跟着变
   - 建议：工单创建时保存配方快照；后续修改产品配方不影响已创建工单。

6. 辅料停用或修改后，已打印二维码/已有工单如何处理
   - 建议：二维码继续按不可变 materialId 判断；已停用辅料只阻止新标签和新配方使用。

7. Excel 导入更新规则
   - 建议：第一版只做“新增 + 校验”，重复编码、引用不存在辅料等整行拒绝；不做静默覆盖更新。

8. 工单是否允许暂停后继续
   - 建议：允许；操作员做到一半退出，下次从当前未完成步骤继续，已完成步骤不重做。

9. 工单编号
   - 建议：系统自动生成，例如 `WO-YYYYMMDD-0001`。

## C. 账号、权限和审批

10. 平板注册账号是否需要后台审核
    - 建议：第一版允许注册但只给普通操作员权限；管理员账号由安装/初始化时生成。

11. 无码放行审批人是否就是电脑管理员
    - 建议：第一版不单独拆“审批员”角色，电脑管理员直接审批。

12. 照片审批驳回后
    - 建议：操作员可以重新拍照并再次申请，原驳回记录保留。

## D. 平板、摄像头与网络

13. 平板具体型号和 Android 版本
    - 需要确认：用于摄像头权限、APK 兼容性和扫码界面适配。

14. 平板是否能安装第三方 APK
    - 需要确认：如果公司平板有安装限制，需要提前准备安装流程。

15. 网络断开时平板能否继续作业
    - 建议：第一版不做离线队列；平板必须连上后端局域网才能操作。

## E. Windows 部署与数据

16. 后端电脑操作系统版本和管理员权限
    - 需要确认：Windows 10/11 具体版本是否允许安装 Windows 服务和修改防火墙。

17. 后端电脑 IP 和端口
    - 建议：后端电脑使用固定 IP，默认端口 8000；浏览器和平板都使用 `http://后端IP:8000`。

18. 数据备份
    - 建议：安装包内置备份功能，可手动备份，也可配置每天自动备份 SQLite 和图片目录。

19. 升级规则
    - 建议：安装包升级时保留数据目录和配置，不覆盖业务数据。

## F. 标签打印

20. 第一版标签打印方式
    - 建议：第一版生成 PDF 标签，用 Windows 系统打印；确定具体打印机型号后再接专用驱动。

21. 标签尺寸和内容
    - 建议：先按 50mm x 30mm 标签设计，包含辅料代号、名称、生产/打印日期和二维码。

## 已明确但可延后

- 电子秤自动读数
- 批次、实际生产日期、到期日期
- 模型自动识别辅料包装图片
- 真实生产阶段的无码放行策略
- 金蝶或其它 ERP 对接
- 多机、云端和容器化部署
