# 国内厨房/小型标签打印机自动打印调研

> 调研日期：2026-09-11
> 决策问题：我们的 PC 系统能否生成二维码标签，由 Windows 电脑向国内厨房/小型标签打印机下发打印指令并自动批量打印，耗材是否可直接粘贴。

## 1. 结论

**可以，技术上已经成熟，关键不是“能不能”，而是“选哪种打印机、用什么方式集成”。**

推荐方案：

1. 采购一台**桌面级热敏标签打印机**，而不是后厨小票打印机。
2. 使用 **TSPL/TSPL2 标签指令协议**生成标签内容并下发打印。
3. PC 端通过**本机打印助手或原始 TCP 9100 网口**自动打印。
4. 标签纸使用**热敏不干胶模切标签纸**，常见 50x30mm 或 60x40mm，打印后可直接撕下粘贴。

这个链路依赖的是打印机原生指令、Windows 驱动/原始打印队列或网络端口，不依赖浏览器弹窗，因此可以实现“后台点击打印 -> 自动连续打印 N 张标签”的效果。

## 2. 技术可行性

国内这些场景的打印机通常分为两类：

| 类型 | 协议 | 二维码能力 | 是否适合本系统 |
|---|---|---|---|
| 桌面/商业标签打印机 | TSPL、TSPL2、CPCL、ZPL 等 | 原生支持 QR 文本指令或位图 | 推荐 |
| 后厨/小票打印机 | ESC/POS | 支持 QR 指令或图片位图 | 不推荐作为主方案 |

标签打印机的原生指令适合我们的场景，因为系统可以直接控制标签尺寸、间隙、打印张数、打印浓度、文本和二维码。

可参考的真实命令示例来自佳博 Windows 示例工程：

```text
SIZE 60 mm,80 mm
GAP 2 mm,0 mm
CLS
DENSITY 7
TEXT ...
QRCODE 400,40,H,4,A,0,"..."
PRINT 1
EOP
```

来源：`vivlong/Gprinter-tool` 的 `GPrinterHttp/Printer.cs`。

## 3. 厂商证据

### 3.1 佳博 Gprinter

- 公开 Windows 示例工程使用的是 `SBSDK_API.dll` 和 `libUsbContorl.dll`，可通过 C# 程序直接识别 USB 打印机并发送指令。
- 示例工程基于 `GP-1324D`，同时提到支持 `GP-9025T`。
- 工程中包含 `QRCODE` 指令、文本、条码、位图、查询打印机状态等能力。
- 工程里还实现了 `GPrinterHttpService`，监听 `127.0.0.1:8848`，通过 HTTP 接收打印内容并调用 USB 打印机。

这个 HTTP 服务形态和我们的系统非常适合：PC 后端只需要 POST 一个打印请求，本机打印助手负责实际 USB 通信。

来源：

- `https://github.com/vivlong/Gprinter-tool`
- 其中 `GPrinterHttp/MainService.cs`
- 其中 `GPrinterHttp/Printer.cs`

### 3.2 汉印 HPRT

- 官方产品页有完整的条码/标签打印机产品线，包括 G42D、N41、D21/D31、HT100/HT130 等桌面和小型标签机。
- G42D 官方页面明确产品为“热敏面单打印机”，打印方式为直接热敏，耗材支持“折叠纸或卷筒纸，模切或连续标签纸”，通信接口为 USB。
- N41 官方页面同样支持“模切或连续标签纸”，通信接口为 USB。
- 官方下载中心明确分类为 Drivers、SDK、Utility、Manuals，也就是厂商提供驱动、SDK、工具和手册下载。
- 官方还提供“汉码标签软件”和 Label Designer，说明其标签打印生态完整。

来源：

- `https://www.hprt.com.cn/ChanPin/131.html`
- `https://www.hprt.com.cn/ChanPin/127.html`
- `https://download.hprt.com/Downloads/`
- `https://www.hprt.com/Product/Label-Printers/`

### 3.3 芯烨 Xprinter

- 公开项目显示芯烨 XP-365B、XP-420B、XP-V3 等标签打印机使用 TSPL/TSPL2。
- 有 Windows 工具直接把标签渲染成 203 DPI 位图，并通过 Windows 原始打印队列 `winspool.drv` 发送 RAW TSPL 数据，支持普通 Windows 驱动队列和 UNC 共享打印机。
- 芯烨官方 SDK 以 C++ 为主，公开 Python 包装示例通过官方 DLL 的 `InitPrinter`、`OpenPort("USB,")`、`PrintSymbol` 直接打印二维码。
- 芯烨型号在开源驱动/工具中支持 USB、蓝牙和 WiFi TCP 9100 原始端口。

来源：

- `https://github.com/Maslodium/printer-tool-xprinter-xp-365b`
- `https://github.com/prodocik/xprinter-xp-v3-linux`
- `https://github.com/SODAVISION-TECH/XprinterSDK-PythonWrapper`

### 3.4 得力 Deli DL-720W

得力官方用户手册 `DL-720C(NEW)\DL-720W(NEW)` 的产品规格页已明确：

- 编程语言：`TSPL`
- 二维码：`QR Code`
- 通信接口：`USB B-Type`、`蓝牙`
- 打印宽度：最大 80 mm
- 耗材宽度：20-92 mm，支持折叠纸、标签纸、卷筒标签纸
- 传感器：缺纸、缝标、黑标、开盖、温度、首张不浪费侦测
- 驱动：Windows 7/8/10/11/XP

官方下载资料包含用户手册 PDF、Windows 驱动、配置工具等；配置工具 RAR 中存在 `POSDLL.dll`，可作为后续调研 Windows 原始打印通道的线索。

结论：

- 对“Windows 本机 + TSPL + USB + 二维码”场景，官方手册已经给出必要规格，DL-720W 基本满足条件。
- 商家“可以通过 USB 连接电脑打印”这句话只证明了 Windows USB 驱动可用，不能单独证明系统可发送 TSPL 自动打印，也不能证明 Android/树莓派可用。
- 采购或打样前仍需确认 TSPL 指令集完整手册、`POSDLL.dll` 的公开接口和授权、目标标签纸宽度/间隙/黑标、二维码中心 logo 后的识别率。

来源：

- `https://www.nbdeli.com/products/productinfo/24524.html`
- `https://www.nbdeli.com/products/productinfo/17036.html`
- `https://www.nbdeli.com/bocupload/2025/06/12/17497084791421e16wu.pdf`

### 3.5 Python/ESC/POS 场景

如果未来被迫使用后厨小票机，Python 侧也有成熟库：

- `python-escpos` 支持文字、图片、条码和二维码。
- 示例中 `p.qr("...")` 可打印二维码。
- 支持 Network、Serial、USB，以及 Windows 上的 `Win32Raw`。

来源：

- `https://github.com/python-escpos/python-escpos`

## 4. 推荐集成方式

### 方案 A：本机打印助手 + TSPL 原始指令（推荐）

流程：

1. 管理员在 PC 后台选择辅料并输入打印张数。
2. 后端生成标签记录，并构造 TSPL 指令，例如尺寸、间隙、文本、二维码内容、打印张数。
3. 后端调用本机打印助手，例如 `http://127.0.0.1:<port>/print`。
4. 打印助手打开打印机、发送指令、返回成功或失败。
5. 后端记录打印批次状态，失败可重试。

优点：

- 浏览器无法静默打印的问题被绕开。
- 支持多张连续打印。
- 便于随 Windows 安装包一起部署。
- 可以与佳博已有 HTTP 服务形态对应，架构上可参考。

实现方式可以是：

- Windows 原始打印队列：通过 `winspool.drv` 发送 RAW 数据，参考 XP-365B 工具。
- 厂商 DLL：通过佳博 `SBSDK_API.dll` 或芯烨官方 SDK 打开 USB 打印机。
- 网络打印机：若打印机支持 WiFi/网口，可直接 TCP 发送到 `IP:9100`。

### 方案 B：后端直接 TCP 9100 发送标签指令

如果采购的打印机支持网络口或 WiFi，后端 Python 可以直接用 socket 把 TSPL 指令发到打印机。优点是少一个本机打印助手组件；缺点是打印机状态、断线重试、USB 型号适配仍需设计。

### 方案 C：厂商 SDK 直连

厂商 SDK 适合 USB 自动发现、状态读取等场景，但通常以 C/C++/Java/C#/Android SDK 为主，Python 需要 `ctypes` 包装。对第一版来说可以作为补充，不作为首选。

### 不推荐：纯浏览器打印

浏览器原生打印会弹打印对话框，无法稳定控制标签尺寸、RAW 指令和批量静默打印。Web Serial、Web Bluetooth、QZ Tray 也可以实现一部分能力，但会增加环境依赖和兼容性风险，不适合第一版。

## 5. 打印机与耗材建议

### 打印机选择

建议采购：

- 2 英寸或更宽的桌面级热敏标签打印机；
- 203 DPI 足够二维码识别；
- 支持 TSPL/TSPL2 或原厂提供 Windows 驱动/SDK；
- 带 USB，最好网络口或 WiFi 作为可选；
- 能安装 50x30mm 或 60x40mm 标签纸。

候选方向：

- 佳博：GP-9025T、GP-1324D 等型号系列；
- 芯烨：XP-365B、XP-420B 等 TSPL 标签机；
- 汉印：G42D、N41、D21/D31 等直接热敏标签机。

注意：佳博和芯烨官网在当前网络环境下返回 503/TLS 错误，无法直接从官网截取最新型号规格；以上型号级结论来自公开 SDK 工程和开源驱动，采购前必须让供应商确认当前型号规格、接口和指令协议。

### 耗材选择

推荐：

- 热敏不干胶标签纸；
- 模切标签纸；
- 根据打印机支持宽度选择，例如 50x30mm 或 60x40mm；
- 标签之间有间隙，或按打印机能力使用黑标定位。

汉印官方产品页已经将“模切或连续标签纸”列为耗材，说明这不是特殊订制纸，而是标签打印机通用耗材。

如果二维码标签需要较长时间保存、接触油脂或高温，可考虑热转印打印机加碳带；如果只是当日/生产周期内使用，直接热敏通常足够。

## 6. 对现有标签功能的落地影响

我们项目已经生成的二维码标签内容可以保持不变，打印环节建议落在 PC Windows 侧：

1. 增加“标签打印批次”记录，包含辅料、张数、打印时间、操作员、状态。
2. 增加本机打印助手的 HTTP 接口契约。
3. 后端根据标签内容和打印机尺寸生成打印有效载荷。
4. 打印成功后才把标签批次标记为已打印。

公司 logo 放二维码中心在技术上是可实现的，可以预渲染二维码位图后叠加 logo，再由 TSPL 的位图命令打印；但二维码中心 logo 会占用纠错区域，必须拿目标扫码枪/平板实测解码率。若稳定性优先，可以先采用“二维码旁放 logo”或“二维码上方放小 logo”。

## 7. 风险与未确认项

1. 具体打印机品牌/型号还未采购，原厂最新规格需要供应商确认。
2. 佳博、芯烨官网当前无法直接访问，官网实时 SDK 页面未取得截图证据。
3. HPRT 官方下载中心有 SDK 分类，但具体哪些 SDK 支持 Windows，需要下载或咨询厂商确认。
4. 二维码中心放公司 logo 会降低容错率，需要实测扫码成功率。
5. 标签尺寸以最终采购打印机和辅料包装大小为准。
6. 长期保存或受热环境是否需要热转印，需要客户确认。

## 8. 建议下一步

- 从佳博、汉印、芯烨中确定 1-2 个候选型号，向供应商确认：USB/网络接口、TSPL/TSPL2 指令、Windows 驱动/SDK、支持的最大/最小标签宽度。
- 采购一台小批量测试机，使用我们现有的标签预览内容打印 20-30 张，用平板扫码验证。
- 确认标签纸规格：50x30mm、60x40mm 或其他尺寸，以及是否需要黑标/间隙定位。
- 确认公司 logo 是否必须放在二维码中心；若必须，做抗干扰和识别率测试。
