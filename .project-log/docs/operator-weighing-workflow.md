# 操作员真实产品制作辅料称量工作流（第一版）

> 用途：描述第一版测试版中，操作员在平板端完成一次“产品制作辅料称量”的完整路径。
> 当前阶段：solution-research。

## 前提

- 电脑后端已部署在 Windows 10/11，平板已安装 Android APK，两者处于同一局域网。
- 平板账号已注册，且工作流所需产品、配方、辅料主数据已由管理员维护。
- 本系统只处理配方中的“需要称量辅料”；基础原材料、投料、混料、包装等步骤不在本流程内。
- 第一版不连接电子秤，重量由操作员读取秤面或其它称量结果后，在平板手动录入，并拍照保存电子秤读数图片。

## 正常流程

### 1. 操作员登录平板

操作员使用自己的账号登录 Android App。

### 2. 获取本单的工作任务

- 如果是后台已经分配好的工单：直接打开工单列表，找到绑定给当前账号的工单。
- 如果是现场新建：选择“创建工单”，选择产品名称，输入目标生产重量，提交后等待后台审批。
- 后台审批通过后，工单才绑定到当前账号，开始生成可执行的辅料称量清单。

### 3. 查看当前工单和称量步骤

系统按产品配方和目标生产重量自动计算：

- 需要称量的辅料清单；
- 每一种辅料的内部代号和名称；
- 每一种辅料应称取的重量；
- 该步骤允许的允差。

工单中的辅料步骤必须按顺序完成，不能跳过。

### 4. 按顺序处理每一个辅料步骤

对每一种辅料，操作员完成“类型确认”和“重量确认”两步。

#### 4.1 类型确认：扫码

操作员拿到现场要称量的辅料实物后，使用平板扫描该辅料包装上的系统自制二维码。

系统读取二维码中的 `materialId`，并与当前工单步骤要求的辅料比较：

- `materialId` 匹配：类型确认通过，系统保存扫码记录。
- 二维码缺失、污损、扫描失败，或不是本系统二维码：进入拍照申请流程。
- 扫描到本系统二维码但 `materialId` 与当前步骤不匹配：系统应阻止进入称重，提示辅料错误，操作员不能把该结果记为类型正确。

#### 4.2 类型确认：无码拍照申请

发生以下情况时，操作员在平板拍摄辅料包装照片：

- 没有本系统二维码；
- 二维码污损、缺失或无法识别；
- 扫描到非本系统二维码/条形码；
- 标签异常导致无法确认。

提交照片和申请原因后，进入“待审批”状态。电脑端审批人审批通过后，该辅料类型才算确认；审批未通过前不能称重。

#### 4.3 重量确认：手动录入 + 读数拍照

类型确认通过后，操作员把辅料放到电子秤上称量，读取秤面实际重量。

第一版电子秤没有接入系统，操作员需要在平板完成两个动作：

1. 手动输入实际重量。
2. 拍摄一张能清楚显示电子秤读数的照片。

数字重量和电子秤读数照片必须一起提交，缺少任一证据都不能完成本步骤。

系统按当前步骤的“目标重量 ± 允差”判断：

- 在允差范围内：同时保存 `manual` 手动读数、电子秤读数照片、操作员、时间；
- 超出允差：提示重量不符，操作员需调整辅料后重新称量、重新输入并重新拍照；
- 输入值非法或明显不合理：拒绝提交并提示重新输入；
- 未拍照或照片模糊无法辨认读数：拒绝提交并提示重新拍照。

#### 4.4 确认本步骤记录落库

完成类型确认和重量确认后，系统必须保存：

- 类型确认方式：扫码记录或拍照申请/审批记录；
- 重量记录：实际重量、电子秤读数照片、数据来源 `manual`、操作员、操作时间；
- 辅料步骤的完成状态。

### 5. 完成所有辅料步骤

所有辅料步骤均按顺序完成，且证据完整后，操作员点击“提交完成”。

系统校验整个工单：

- 每个步骤都已完成类型确认；
- 每个步骤都有数字重量记录和电子秤读数照片；
- 证据完整、记录来源明确；
- 没有未完成的中间步骤。

校验通过后，工单状态变为“已完成”。

## 异常与辅助情况

### 照片申请 pending

操作员提交无码拍照申请后，工单当前步骤保持等待，不能继续称重。电脑端审批通过后，流程才继续。

### 称重读数照片异常

电子秤读数照片缺失、太暗、模糊、未拍到实际读数时，不能完成该重量步骤；操作员需要重新称量并重新拍摄。

### 接管工单

如果工单绑定给其他账号，操作员可以在平板查看并申请接管；后台审批通过后，工单归当前申请账号操作。

### 撤销/删除工单

操作员可以在平板申请撤销或删除工单，但需要后台审批；后台也可以直接撤销或删除。撤销/删除后仍保留历史记录和证据。

### 标签异常

自制标签缺失、污损或扫描失败时，不直接放行，统一走拍照申请审批。
