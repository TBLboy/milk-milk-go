# Q-014 辅料码映射分析 Brief

> 用途：把这份文档连同手头的二维码/条形码图片一起发给 GPT，请它做“现有辅料包装码是否能可靠映射到公司内部代号”的分析。
> 当前阶段：业务澄清，不要求出代码，优先产出判断规则、样例整理表和映射方案。

## 1. 请你帮我解决的问题

我们正在做一个牛奶生产工厂的辅料称重防错系统。第一版会使用平板摄像头扫码，把扫码结果对应到公司内部的辅料代号，例如 `A1`、`E2`。现场辅料包装不统一，有二维码、条形码、无码，而且二维码扫出来往往是**辅料供应商自己的产品溯源信息**。

请基于我提供的二维码/条形码图片和以下背景，回答：

1. 这些码分别是什么类型，原始内容是什么结构？
2. 同一个辅料的不同包装/批次之间，扫码内容是否稳定？哪些码可以可靠用于类型识别，哪些不能？
3. 对可以使用的码，建议采用哪种匹配方式：整串精确匹配、标准化后匹配、按 URL 参数匹配、按固定前缀/前缀解析、正则提取等？
4. 哪些码应判定为“无法自动识别”，走拍照申请审批流程？
5. 请给出一个可以用于整理映射数据的表格模板，字段应该能直接指导后续主数据维护。

请不要假设我提供的图片背后一定存在“一个码对应一个辅料”的固定规则；如果你判断现场码太乱或存在碰撞风险，请明确指出来。

## 2. 项目背景

- 这是牛奶生产公司的辅料称重防错系统，核心目标是在称重前确认“辅料类型正确、重量正确”。
- 系统是独立系统，不接金蝶。
- 电脑端负责后端、数据库和后台管理；平板端是现场主要业务操作端，通过局域网连接电脑端。
- 平板端注册账号都是普通操作员账号；电脑后台是预置管理员账号。
- 操作员创建工单，后台审批通过后绑定到该账号；只有绑定账号可操作该工单。
- 配方按“每吨成品需要多少辅料”录入，系统按目标生产重量等比换算应称重量。
- 每个辅料步骤需要保留类型确认证据和实际重量记录，工单全部步骤完成且证据完整后才能提交完成。
- 所有工单、扫码记录、图片和审批证据长期保存，不物理删除。

## 3. 第一版识别方案

第一版已经确定采用混合识别方案：

- 能有效扫描的现有二维码/条形码，在后台维护“识别值列表”，映射到公司内部辅料代号。
- 扫码后，系统拿扫描结果和当前工单要求的辅料匹配；匹配成功才自动放行。
- 无码、无效码、未映射码、供应商动态溯源二维码等无法稳定匹配的码，走“拍照 + 手动选择辅料 + 后台审批”流程。
- 第一版不强制贴自制二维码；自制二维码贴纸作为后续增强。

因此，目前最需要确认的是：

- 现有码的原始内容到底是什么？
- 是否可以稳定建立“原始码值 -> 内部代号”的映射？
- 如果可以，映射表如何进行维护和匹配？

## 4. 现场事实

- 辅料包装类型不统一，至少包括：
  - 塑料桶，类似汽油桶形状
  - 纸箱
  - 蛇皮袋
- 有码/无码混合；蛇皮袋和纸箱可能没有码。
- 有码的辅料里，有的贴二维码，有的贴条形码。
- 部分条形码扫描后是无效结果。
- 二维码扫描出来的内容通常是辅料供应商自己的产品溯源信息。
- 辅料从不同供应商购买，包装上不一定写公司内部代号。
- 公司内部不直接叫辅料名称，而是使用自己的代号，例如 `A1`、`E2`。

## 5. 期望行为 vs 现场实际

期望行为：

```text
平板扫码 -> 得到原始码值 -> 系统映射到内部代号 A1/E2
-> 与当前工单要求的辅料比较 -> 匹配则放行，不匹配则拒绝
```

现场实际：

```text
包装上有二维码/条形码/没有码
二维码可能是供应商溯源网页或动态批次内容
条形码可能扫不出
包装上没有统一的内部代号标识
```

所以现实可能会按三种情况落地：

```text
情况 1：码值稳定且可映射 -> 自动识别
情况 2：码值不稳定，但能提取稳定规则 -> 按规则映射
情况 3：无法可靠映射 -> 拍照申请审批
```

## 8. 我们已知和未知的内容

已知：

- 第一版采用混合识别方案。
- 内部使用 `A1/E2` 类代号。
- 不强制贴码，拍照申请审批已确认。
- 系统后续可以支持后台维护一个辅料多个码值，也可以支持批量导入。
- 第一版没有扫码枪，平板摄像头是主识别设备。

未知/需要你帮助判断：

- 现有二维码原始内容具体是什么，是否每包一样。
- 现有条形码类型和内容是什么，为什么有些扫不出。
- 供应商二维码是不是同一个物料统一前缀、不同批次不同编号。
- 哪些码可以安全自动匹配，哪些必须走拍照申请。
