# 当前需求摘要

- 当前目标：为牛奶生产企业提供辅料称重防错能力，确保生产过程中称取辅料的类型和重量正确
- 当前基线：`REQ-001` v4（`active` / `approved`）

## REQ-001 已批准基线

- 状态：`REQ-001` 已由用户确认批准，第一版按此基线执行
- 边界：独立系统、不连接金蝶；电脑后端/数据库 + 平板 App 局域网协同；第一版以公司自制二维码为主确认辅料类型，无码或标签异常走拍照申请审批
- 主数据：产品、配方和辅料由用户维护，支持后台手工录入和 Excel 模板导入/导出；辅料和产品配方双端录入但仅管理员可操作
- 称重：第一版不连接电子秤，称重结果由平板手动输入并标记为“手动读数”，同时必须拍摄并保存电子秤读数照片；数字重量和照片一起作为称重证据；允差放设置界面，稳定参数后续电子秤接入时再启用
- 工单：平板创建/后台审批/账号绑定/接管审批；按顺序完成并留存证据；撤销/删除后仍长期保留记录
- 标签：后台选择辅料和张数打印，系统记录 `printedAt`；第一版不管理实际生产日期和到期日期
- 技术方向：后端默认 Windows 11；平板为最新 Android 系统并支持安装 APK；电脑端使用浏览器管理端；技术栈确认采用 Python FastAPI + SQLite + Android 原生 Kotlin，浏览器管理端按 React/Vite 静态文件由 FastAPI 托管
- 架构输入默认：称重按净重以 kg 输入；电子秤读数照片需同时包含材料和读数；允差默认取目标重量 1% 和 5g 中的较大值且可配置；工单创建时保存配方快照；工单允许暂停续作；Excel 导入采用新增和校验，不静默覆盖；无码放行审批人为电脑管理员；平板注册账号为普通操作员；第一版不提供平板离线队列；安装包内置自动备份数据库
- 非阻塞未决项：标签打印机具体型号、真实生产阶段无码放行策略；电子秤从第一版范围移除，单独留到后续版本
- 下一步：进入架构设计，定义模块、接口、数据流和失败路径
- 范围内（初步）：
  - 按产品配方和目标生产重量计算应称辅料清单
  - 扫码或拍摄包装图片确认辅料类型
  - 操作员录入称量结果、拍摄电子秤读数照片并校验目标重量
  - 称重按净重记录，单位统一 kg，读数照片同时包含材料和电子秤读数
  - 独立系统交付，不连接金蝶
  - 系统内置产品、产品配料和辅料信息管理
  - 主数据支持后台手工录入和 Excel 模板导入/导出；导入前校验必填项、重复编码和配方引用关系，失败行给出原因，不覆盖有效数据
  - 辅料信息包含中文名称、选填英文名称、公司内部代号、默认保质期和多张包装图片；电脑端可从本地图片选择，平板端可从相册选择或直接拍摄
  - 辅料字段规则：materialId 系统自动生成且不可变；materialCode、中文名称、默认保质期必填；英文名称选填；enabled 默认启用
  - 辅料和产品配方录入均支持电脑端和平板端，但仅管理员可操作；APP 区分普通操作员和管理员，管理功能只对管理员开放
  - 产品配方包含产品名称和各辅料每吨用量；录入时只能从现有辅料库选择辅料，缺少的辅料先录入再录产品配方，产品录入不涉及图片
  - 现场操作首选平板，扫码枪作为次选
- 系统架构（用户 2026-09-08 反馈）：
  - 电脑端：数据库 + 后端服务系统
  - 平板端：App 通过局域网连接电脑后端
  - 支持多个平板同时工作；操作员注册账号，通过账号区分身份
  - 平板端注册的账号为普通操作员账号，不能进入后台；电脑后台管理员账号为预置账号，可创建和管理普通账号
  - 操作员主要在 App 创建工单、选择产品，按步骤准备辅料
  - 称重记录、扫码/图片和审批证据长期保存，不物理删除
  - 配方按“每吨成品需要多少辅料”录入，系统按目标生产重量等比换算
  - 现场包装不统一：塑料桶、纸箱、蛇皮袋；部分无码，部分条码扫描无效，二维码多为供应商溯源信息；内部使用 A1/E2 类辅料代号
  - 第一版采用公司自制二维码为主：扫码解析本系统标签的 materialId，与工单要求匹配；供应商原有二维码/条码不作为核心身份；无码、标签异常或无法识别时走拍照申请审批
  - 外部《辅料自制二维码方案设计说明》核心方向适合：不可变 materialId、后台主数据为真实数据源、labelId 标签记录、扫码按 materialId 判断
  - 自制二维码标签流程已确认：电脑后台管理员生成/打印；不录入实际生产日期，以标签打印日期作为二维码标签日期；到期日期校验暂不纳入第一版；每次打印生成独立 labelId，同一种辅料可共用 materialId；标签状态保留 ACTIVE/VOID；粘贴后扫码复核；无码或标签异常走拍照审批
  - 后台标签打印界面：选择辅料、选择打印张数、点击打印；系统自动记录当前打印时间并发送打印指令；打印机需新购并配合系统接入，具体型号延后确定
  - 工单绑定操作员账号：平板创建工单后由后台审批，审批通过后绑定创建账号；其他账号可申请接管，后台审批后重新绑定；后台也可创建工单并指定绑定账号
  - 每个辅料步骤：扫码或拍照确认类型 -> 上称称重 -> 手动输入秤面读数并拍照保存
  - 工单必须按顺序完成全部辅料步骤后才可提交完成；每个辅料保留二维码/图片证据和实际重量记录
  - 平板端可申请撤销/删除工单，后台审批通过后生效；后台也可以撤销/删除；删除保留全部历史记录，不物理删除
- 辅料确认方案（用户 2026-09-08 反馈）：
  - 最终目标：有二维码时自动识别；没有二维码时拍照，后端模型与辅料包装图片自动对比；识别不符但实际正确时可申请放行，并附理由和图片/视频证据
  - 第一版范围：实现本系统自制二维码识别和拍照申请/审批流程；模型自动识别放后续版本；无码辅料测试版采用“平板申请、电脑审批、通过后才称重”（Q-005 已确认）
  - 拍照和申请资料均作为工单证据留痕
